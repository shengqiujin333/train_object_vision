## 0. 交付边界与环境声明

### 0.1 本 capability 交付什么

- 交付：按测试层级（逻辑 / 预览功能 / 板端集成 / 端到端）组织的可执行测试方案，每条用例给出**准备、刺激、观测、判据、清理、证据**六要素；按 PRD P0 建冒烟集；给故障注入目录；给回归集；给需求-用例覆盖矩阵；给另附的 E2E 计划（`docs/hmi/E2E_PLAN.md`）。
- 不交付：测试执行结果与证据文件本身（归执行能力）；MCU/固件/板上嵌入式 Linux 联调（归 `embedded_tester`）；上电/电气/功耗（归硬件职责）；模型精度与训练验证（归模型职责——本版各相机可先用同一模型，精度验收不在本设计内，见 §11 缺口）。
- 本轮未执行任何测试。**主机无 C/C++ 工具链（E-00 有证据缺口）、`rk3588_build`/`deploy`/`verify` 与相机流入口当前 `unavailable_for_current_capability`、设备工具后端已禁用**；设计中所有"板端/真机"结果均为待执行状态，不得写成已通过；缺口按 §1 三态登记，不互相代替。

### 0.2 判据来源声明

- 报警级别映射严格按 PRD §8.2（前方人员/障碍物→一级、轮轨明显异常→一级、受电弓异常→二级、车门未关严→二级、前方主摄离线/冻结→二级、侧视离线→三级），测试不另造判据。
- 流状态机取值、非 LIVE 禁止旧帧充实时画面、角色隔离等约束以交互方案 v2 §7.1/§8 与桌面设计 v2 §6.2/§7.2 为准。
- 状态契约以交互方案 v2 §7.2 / 桌面设计 v2 §7.1 为准：检测职责按 `ai_enabled`+`ai_profile`（front/pantograph/wheel_rail/cab_door/none）驱动，不做配置外推断；`integration_state(probing/reachable/unreachable/unconfigured/unverified)` 与 NVR `channel_mapping=未配置` 按优于 交互方案 v2 §11#13 的口径验收"显式中性 + 无自动修改入口"。
- 所有阈值（多帧确认帧数/时间、冻结窗口、重连阈值、容差、存储阈值、片段时长）来自 `config/thresholds.yaml` 等配置文件；**测试断言引用配置值**（记作 `[cfg]`），不写死数值；配置缺失/非法本身是被测对象（TC-CFG-01..03）。
- 渲染路径判据受 `render_path_spike.md` §7 约束：未取得板端实测（当前 ITEM-002 UNMEASURED）前默认 `cpu`、`gl` 为可开启候选，测试不得把 `gl` 当已选主路径。
- 未确认项（Q-04/05/07/08、Q-NVR、V-01/V-02）相关功能按"未接入/不适用"呈现验收；本期无红外（PRD §13）——模式相关需求仅验收"可见光 + 红外未接入，无切换控件"（交互方案 v2 §11#14）。

**资源缺口与替代（来自当前输入，非新增必备设备）**：
1. `.162/.163/.165/.167` 四路相机凭据/URL 未核验（E-10）→ ENV-C/D 用**录制文件源（filesrc/uridecodebin 循环）**替代真实流，结论分开记录"文件源已验证/真实相机未执行"。
2. 侧视/车顶/车底/司机室四路编码与分辨率仅"按左侧相机档案预期"（`expected_from_left_camera_profile_not_measured`）→ 真机档须逐路实测再记入注册表，不得按`.160` 档案预设通过（ITEM-002/ITEM-004 观察点）。
3. NVR（`192.168.1.4`）账户/协议/6 路通道映射未提供（E-11）→ 连续录像回放测试用 **`NvrRecordingProvider` 的 unavailable 分支 + 本机保护片段**验收，通道映射验收"未配置"显式呈现（交互方案 v2 §11#13）；接口确认后补真回调取用例（TC-PLY-* ENV-D 档）。
4. 车速/门磁/声音（Q-04/05/07）→ 顶部车速、门磁输入、音频分别以"未接入"状态展示验收；声音测试降级为 `IAudioNotifier` 打桩观察调用记录（不假定音箱/蜂鸣器存在）。

## 2. 度量定义与观测窗（避免口说无凭）

| 度量 | 定义（测量起止点） | 观测窗/方式 | 容差 |
|---|---|---|---|
| 流 FPS | StreamManager 发出的帧到达计数 / 时间 | 5s 滑窗（沿用 `cam_viewer.py` 语义），每 5s 采样一次并写 `stream_events` | 目标值来自 `cameras.yaml display_fps`；±10% 记录不判失败 |
| 冻结判定 | 最近一帧到达时间与"now"之差超过 `thresholds.yaml` 冻结阈值 `[cfg]` | 由 UI 状态 + DB 时间戳复核 | 以配置为准 |
| 端到端报警延迟 | 目标进入危险区且满足多帧确认的最后一帧 `arrival_monotonic` → UI 显示一级横幅`ts_wall_ms` | 结构化日志插桩（观测 ≥10 次取分布） | 当前版本**指标未冻结**（PRD §12：须现场实测后冻结）→ 记录分布，不判 pass/fail |
| 三联同步偏差 | 回放中同屏截图各路播放时间戳的极差 | 每次回放取 3 个时刻截图对比 | 漂移超过 `thresholds.yaml` 同步阈值 `[cfg]` 时必须显式提示（判据是"提示存在"，提示本身允许） |
| 保护片段时长 | 片段文件实际媒体时长 vs 配置 `前30s/后60s（可配置）` | ffprobe/board 端分段时长记录 | ±1s（分片粒度内） |
| CPU/NPU/温度 | `/proc/stat`、`/sys/kernel/debug/rknpu/load`、`/sys/class/thermal/*` | `device_health` 采样周期 `[cfg]` | 记录，不单点判失败；连续越阈值须触发告警（TC-HLT-05） |
| UI 可见性 | 两档分辨率（1920×1080 / 1280×720）下 P0 元素截图 | 调窗或改分辨率 | 不滚动即全部可见 |

## 6. P0 冒烟集（SMOKE，全展开；组成 REG 骨架）

### TC-SMOKE-01 应用启动空态（无任何相机可达时）
- 准备：`config/cameras.yaml` 正常；无相机可达（或 ENV-A 模拟"全部 OFFLINE"）。
- 刺激：启动应用。
- 观测：P1 页面出现；三联槽位渲染"连接中→离线/重连中"占位与最近帧时间占位（无实时旧帧）；顶部状态条"未接入"的车速/模式正确显示；关键状态区摄像头项呈异常且可点击跳转。
- 判据：无崩溃退出；**任何位置均不得显示旧帧为实时（交互方案 v2 §7.1 硬约束）**。
- 清理：退出。证据：启动期结构化日志 + 全屏截图。
