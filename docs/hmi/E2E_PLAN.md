## 2. E2E-01 详细步骤（示范条目，其余旅程按相同六要素执行）

- 准备：应用处于 LIVE 三路（前方/左/右）；模拟检测序列就绪（ENV-A/C）或真人进入前方轨道（ENV-D，用户执行）；DB/日志清空标记时间点。
- 刺激：注入目标进入危险区并满足多帧确认。
- 观测（时序断言）：
  1. ≤ 确认阈值满足后尽快显示一级横幅（红色/实心三角/文字“一级”）；
  2. 报警条五要素齐备；快照生成且元数据（算法/模型版本/置信度/距离）可查；
  3. 片段登记 recording_segments（complete=true），事件 record_available 真实；
  4. 点击[确认]：横幅可关闭、事件仍可检索；
  5. 点击[查看回放]：P3 定位报警时刻，左/前/右三路同步时间轴；
  6. 四跳按钮全部有效；时间轴报警区段显著色标。
- 判据：以上 6 步全部成立为一轮 pass；每轮间隔重置后独立记录（≥3 轮取稳定性）。
- 清理：删除/归档注入状态，DB 保留为证据快照。
- 证据：`docs/hmi/test_evidence/E2E-01/<轮次>/`（DB json 导出 + 截图 + 片段清单 + 日志摘录 + 注入参数）。

## 3. 通过准则与失败路由

- E2E 升降级：ENV-A 全绿才升 ENV-C/D 执行；板端档失败若根因属板端资源/驱动/BSP（如 E-01..E-09 缺项）→ 记录为依赖缺口交平台/嵌入式职责，不算软件功能失败；属软件行为则按 TEST_DESIGN §3/§4 交回实现修复。
- E2E-02/E2E-05 属现场执行项：软件侧以“注入桩通过 + 可复现步骤/字段记录移交”为完成态；现场执行结果不回填本计划。设备工具已禁用，本计划不预设任何物理测试已执行。

## 4. 与 TEST_DESIGN 的衔接

- 故障注入目录/度量定义/证据规范全部沿用 `docs/hmi/TEST_DESIGN.md` §2/§3/§9，不在本计划重述数值。
- 回归入口：版本发布前必跑 E2E-01 + E2E-04（故障马拉松）+ REG 序列（TEST_DESIGN §8）。
