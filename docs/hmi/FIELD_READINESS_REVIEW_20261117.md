# 现场就绪度评估（2026-11-17）

> 对象：RK3588 车载监控 HMI（`railhmi` 0.1.0，六路可见光 + BLE 门磁 + NVR 回放 + 三路 AI）。
> 本文回答业主提出的五个问题，并记录本轮新增的两个功能。结论只依据板端实测与仓库证据，
> 未做的部分明确写"未做"，不按设计文档推定。

---

## 0. 本轮新增（已交付并验证）

### 0.1 隐藏维护模式

- 默认导航只有 4 页：实时监控 / 报警中心 / 历史录像 / 全摄像头；
  **AI 调试、设备维护两页隐藏**（`main.qml` 的 `navEntries` 过滤）。
- 屏幕**左下角有一个不可见的 72×56 热区**：连续点击 **10 次**（每次间隔需 <5 秒，否则计数清零）
  → 弹出「维护模式密码」输入框 → 输入固定密码 **`sjztmxny`** → 解锁。
- 解锁后：导航出现 **AI 调试 / 设备维护**，并直接进入设备维护页；左下角热区变成**可见的
  「退出维护」按钮**。点它即退出：两页重新隐藏、页面回到实时监控。
- 板端实测：10 次点击弹框（截图 `hmi_verify/round7/H2.png`）、密码正确解锁（`U1.png/U2.png`）、
  解锁后 6 个导航项 + 左下角「退出维护」、键盘在解锁后自动收起。

> 说明：密码是**固定值**、写在 QML 里，能挡住误触，但挡不住有心人（反编译即可读到）。
> 若要真正防越权，应改为系统账号 + 角色（core 里已有权限矩阵，见 §1 的缺口）。

### 0.2 U 盘导出（报警数据 + 维护日志）

- 设备维护页「功能操作」新增 **`U盘导出`**：把 **报警数据（CSV）**、**设备维护日志（TXT）**
  和一份 **manifest.txt**（版本/导出时间/条数）写入 U 盘
  `railhmi-export-YYYYmmdd-HHMMSS/` 目录。
- U 盘识别：读 `/proc/mounts`，只认 `/dev/sd*`、`/dev/mmcblk*` 且在 `/media`、`/run/media`、`/mnt`
  下的**可写**挂载点；**没插 U 盘时明确提示**「未检测到可用 U 盘」，不假装成功。
- 板端实测（用 `RAILHMI_USB_DIR` 指向临时目录模拟 U 盘）：

```
/tmp/usbtest/railhmi-export-20261117-182018/maintenance-log.txt 157 bytes
/tmp/usbtest/railhmi-export-20261117-182018/alarms.csv            1 bytes
/tmp/usbtest/railhmi-export-20261117-182018/manifest.txt         83 bytes
[maint] U盘导出：已写入 …（维护日志 2 行 / 报警 0 条）
```

> 报警 0 条是因为**报警库里目前没有持久化事件**（见 §1 的"事件不落库"），不是导出失败。

## 1. 整体功能是否完整、是否闭环

### 1.1 分域评估

| 域 | 现在能做什么（实测/代码证据） | 闭环度 | 缺口 |
|---|---|---|---|
| 六路视频 | 六路并发取流、25fps、断流 8s 自动重建（退避 5→60s）、冻结/离线六态、非 LIVE 不用旧帧 | **闭环** | 无（长跑统计仍待做） |
| AI 推理 | 三路（前/受电弓/轮轨）真跑 RKNN；车前方两阶段（轨道掩码 ∩ 人/物）；P1 实时画框 + 报警闪红框；P5 可换模型 | **半闭环** | ① 三路共用同一检测模型（临时）；② 当前机位画面里没有轨道掩码 → 只显示框、不产生"轨道内"报警；③ 无现场微调数据 |
| 报警呈现 | P1 报警条 + 顶栏 + P2 报警中心（级别/筛选/确认/查看录像） | **半闭环** | **报警事件只在内存**：进程重启即清空，P2 不会保留历史；快照未落盘 |
| 报警录像 | NVR 历史查询/回放（已实机核对 6 通道映射）；本机保护片段（core + solidify）已实现 | **未闭环** | 报警 → 自动固化片段 → 回放定位这条链**没有接到事件上**；本机连续录像未启用 |
| 门磁 | BLE HCI 直读，1~2s 识别；顶栏/P1/P2/P6 联动 | **闭环** | 电池低电量只在维护日志提示，未进报警中心 |
| 录像机 | TCP 探测 + Digest 登录 + 会话过期自动重登 + 通道/录像查询 + 回放 | **闭环** | NVR 侧录像完整性（缺段）未校验 |
| 设备维护 | 日志（保存/导出/U 盘）、摄像头 ping、NVR 登录、蓝牙扫描、故障自检（含 WiFi 驱动）、系统信息 | **闭环** | 见 §3 的缺口项 |
| 权限/角色 | core 有 13 权限 × 4 角色矩阵；P3 导出门禁按配置 | **未闭环** | 界面无角色切换、无登录；当前固定 admin，权限矩阵实际上没被用来限制操作 |
| 存储/健康 | 顶栏内存/CPU/NPU 真实采样；磁盘余量只在系统信息里显示 | **部分** | 无"存储低于阈值"的报警（PRD DATA-003 要求提前报警） |

### 1.2 结论

- **监视 + 提示闭环成立**：六路画面、AI 框、报警条、门磁状态、NVR 状态都能实时反映。
- **"事后可追溯"闭环不成立**：报警不落库、快照不存、本机片段未与事件绑定，
  断电/重启后 P2 是空的；现在能追溯的只有 NVR 里按时间查的录像。
- 因此对外表述建议：**当前是可用的"辅助监视 + 提示"版本，不是"事件可审计"版本**。
  要闭环，优先级最高的是 §6 的 R1（事件落库 + 快照 + 片段固化）。

## 2. 界面里哪些是无用/低价值功能

| 位置 | 功能 | 问题 | 建议 |
|---|---|---|---|
| 顶栏 | 系统健康「未接入」 | 没有采样源，长期灰着 | 接入 health 采样，或删掉该项 |
| 顶栏 | 车辆状态（人工置位） | 无车速/GPS 源，点了只是写个状态 | 保留（现场明确要），但建议置灰+标注"人工" |
| P2 报警中心 | 类型筛选「主机」「NVR」 | 目前没有事件生产者，永远空态 | 保留占位可以，但空态文案要说明"未接入事件源" |
| P2 | 日期筛选默认 30 天 | 现场常用当天/昨天，多点两下 | 默认"今天"或"最近 3 天"，可配 |
| P3 历史录像 | 「导出」已删除、倍速已删除 | 符合现场（受权限与无键盘约束） | 保持 |
| P5 AI 调试 | 叠加开关「掩码」 | 没有掩码数据可画，开了也没效果 | 要么接掩码渲染，要么先隐藏该开关 |
| P4 全摄像头 | 侧视格的「广角·无检测」徽标 | 侧视本来就不检测，徽标是噪声 | 去掉无 AI 路的徽标 |
| P6 | 六个操作按钮 | 都可用，但「U盘导出」和「保存/导出」功能重叠 | 保留：前者导到 U 盘，后者落本机 logs/ |

## 3. 现场可能出现的故障 & 维护页能否定位

### 3.1 故障清单与可测性

| # | 故障 | 现场表现 | 维护页现在能否定位 | 需要补的能力 |
|---|---|---|---|---|
| 1 | 相机断电/网线松 | 单路黑屏、顶栏 x/6 | **能**：摄像头检测 ping + 自检逐路状态 | — |
| 2 | 相机 IP 被改/IP 冲突 | 单路连不上，ping 通但 RTSP 失败 | **部分**：ping 通但取流失败会显示"连接中/失败" | 增加"RTSP 端口 554 探测 + 认证探测" |
| 3 | 码流参数被改（分辨率/编码） | 黑屏或花屏 | **不能** | 维护页增加"拉流参数读取"（ffprobe 摘要） |
| 4 | NVR 掉线 | 顶栏 NVR异常 | **能**：TCP 探测 + 检测按钮 | — |
| 5 | NVR 账号/权限变更 | 回放报认证失败/无权限 | **能**：会话过期自动重登 + 失败报文进日志 | — |
| 6 | NVR 硬盘满/录像缺失 | 能查通道但查不到录像 | **不能** | 增加"按通道+日期查录像条数/时长"自检 |
| 7 | 本机磁盘满 | 日志/片段写失败 | **部分**：系统信息里有磁盘余量，无阈值判定 | 加阈值判定 + 顶栏告警（PRD DATA-003） |
| 8 | BLE 门磁没电/离线 | 顶栏"传感器异常" | **能**：蓝牙扫描 + 自检 | 电池低电量建议进报警中心 |
| 9 | 门磁被别的 BLE 干扰 | 门态跳变 | **部分**：扫描列出所有候选设备与 RSSI | 增加"非 T1 设备计数"提示 |
| 10 | WiFi 断开 | 远程连不上，本地仍工作 | **能**：自检的 WiFi 段（驱动/连接/信号/IP） | — |
| 11 | WiFi 驱动异常 | 无 wlan0 或频繁掉线 | **能**：驱动/模块/dmesg 三条 | 增加重连次数统计 |
| 12 | 相机云台被手动转走 | 前方画面偏 | **不能**（云台卡片已按要求删除） | 若恢复云台能力，建议放"高级"子页 |
| 13 | 系统时间漂移 | 录像时间对不上 | **不能** | 自检增加 NTP/系统时间与 NVR 时间比对 |
| 14 | 温度过高/降频 | 帧率下降 | **部分**：系统信息有 CPU/NPU 负载，无温度 | 补温度采样（thermal_zone） |
| 15 | 主机异常断电 | 重启后能否自恢复 | **能**：systemd 自启 + 启动恢复浮层 | 建议加"上次异常退出"标记 |
| 16 | 程序卡死但进程在 | 画面不动 | **不能**（无心跳监控） | 加看门狗：帧时间超过 N 秒即重启服务 |

**结论**：16 类里现在能明确定位 7 类、部分定位 5 类、完全不能定位 4 类（码流参数、NVR 录像完整性、
时间同步、卡死）。建议按 §6 的 R3 补 4 个自检项，成本都不高。

### 3.2 建议的维护页自检补充（按性价比排序）

1. **卡死看门狗**（最高价值）：连续 10s 无新帧 → 自动 `systemctl restart railhmi`，并记录一次事件。
2. **存储阈值**：`/opt/railhmi` 与录像盘剩余 <10% 进顶栏黄/红。
3. **时间同步**：比较系统时间与 NVR 返回时间，偏差 >5s 提示。
4. **NVR 录像完整性**：按通道+昨天查一次，返回 0 条即提示。

## 4. 升级是否方便

### 4.1 软件升级（现状：较方便，但有一次踩坑）

```sh
cd /home/admin/railhmi-ui-fix/app && ./build.sh Release
cd .. && sudo bash packaging/install.sh     # 现在带 md5 自校验，装错会直接报错
sudo systemctl restart railhmi
```

- 已具备：`packaging/UPGRADE.md` 全流程（备份、验收 10 条、回滚、常见问题）；
  systemd 常驻 + `Restart=always`；`install.sh` 幂等 + **md5 自校验** + **CRLF 自查**。
- 待补：
  1. **一键回滚脚本**（现在要手工从 `/opt/railhmi/backup/<tag>` 拷回）；
  2. 版本号未随功能递增（一直是 0.1.0），现场无法凭界面确认装的是哪版；
  3. 没有 A/B 分区或发布包签名，误刷无法自证。

### 4.2 AI 模型升级（现状：配置化，比软件更灵活）

- 模型名/路径全部来自 `app/config/app.yaml`，放新 `.rknn` 到目录 + 改 `models` 即可，**不用重编译**；
- P5 页面可现场切换模型（当前仅检测/分割两类候选），切换失败会显式报 `MODEL_LOAD_FAILED`；
- 待补：
  1. **切换不持久**（重启回到配置文件里的模型）；
  2. 缺少模型清单页（当前只显示名字/版本，没有精度/输入尺寸/大小）；
  3. 缺"模型回滚"（切错模型后只能再切回去）。

## 5. AI 调试页怎么用（建议）

现状：只读展示（框/置信度/距离/FPS/端到端延迟/模型版本）+ 模型切换 + 四个叠加开关
（框/ROI/文字/掩码，默认关）。对现场排查来说"能看不能用"。

建议按这个顺序补（都在 P5，不改主流程）：

| 优先级 | 功能 | 价值 |
|---|---|---|
| P0 | **每路 AI 启用/关闭开关** | 现场可临时关掉误报多的路（比如对着墙的受电弓），不用改配置重启；也是你说的那条 |
| P0 | **阈值滑条（0.15~0.6）+ 落配置** | 现在改阈值要改 yaml 重启；现场调参最常做的事 |
| P1 | **ROI 框选（画轨道区/危险区）** | 车前方"轨道内才算"目前依赖分割模型；画个 ROI 立刻可用（对无轨道画面的现场尤其重要） |
| P1 | **采集样本（保存当前帧+框）** | 为后续微调准备数据，一键存到 U 盘 |
| P2 | **误报标记** | 记录时间/相机/框/置信度到 CSV，作为阈值与模型的评估依据 |
| P2 | 指标曲线（FPS/延迟/丢帧） | 现在只有瞬时值，长跑问题看不出来 |

> 特别注意：**每路开关必须真的重建 worker**（`AiRuntime` 里按 camera_ids 重建），
> 而不是只在 UI 上隐藏结果——否则"关了还在跑"会误导排查。

## 6. 建议的下一步（按优先级）

| 编号 | 事项 | 理由 |
|---|---|---|
| R1 | 报警事件落库 + 快照 + 保护片段绑定 | 让"报警→回放→导出"真正闭环，也是 U 盘导出有意义的前提 |
