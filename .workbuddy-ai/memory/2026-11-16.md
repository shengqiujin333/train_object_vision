## 实现与关键结论
- **P3**：`P3Replay.qml` 改为整页宽度 `replayVideoArea`（1168x524），单/多画面严格 16:9（按可用高度反推宽度并居中），`VideoFrame.fillMode: 1`（Cover，`Qt::KeepAspectRatioByExpanding` + clipRect）消除黑边；`keyframeStrip.visible: thumbs.length > 0` 使空条高度归零；右侧详情栏整栏删除，`detailRecordBar` 收进 sourceRow 成紧凑条（76x32）。底部只留游标时间/时间轴/播放/-30s/报警时刻/+30s/+60s。左右留白是「保持 16:9 且占满可用高度」的取舍，不是黑边；若强行铺满 1168x524 会裁掉约 18% 画面内容，现场监控不宜裁剪。
- **P2**：core 新增 `alarm_category / alarm_category_label / parse_alarm_category / alarm_category_tokens` 四个固定 token（camera/door/nvr/host）；`AlarmFilter.has_category/category` 与 `RailhmiAlarmModel::query(..., category)`；QML 第二行五个固定 chip 互斥单选（`fCategory` / `selectCategory()`）。NVR/主机当前无事件生产者时如实空态，不伪造。
- **顶栏**：新增 `SystemMetricsRuntime` + `ResourceMeters.qml`（两行紧凑）。内存 `(MemTotal-MemAvailable)/MemTotal` 读 `/proc/meminfo`；逐核 CPU 用 `/proc/stat` 两次差值；逐核 NPU 读 `/sys/kernel/debug/rknpu/load`（Core0/1/2）；debugfs 不可读退到 `/sys/class/devfreq/fdab0000.npu/load` 并显式标注「聚合」，绝不复制成多核；取不到填 -1 显示「—」/「未接入」。`packaging/railhmi.service` 加 `ExecStartPre=-+/bin/chmod 0444 /sys/kernel/debug/rknpu/load`。
- **门磁加速（根因）**：改造前**不是多线程**，BlueZ 全在 GUI 线程以 `QDBus::Block` 同步调用，且 `PropertiesChanged` 订阅接口误写成不存在的 `org.freedesktop.DBus.PropertiesChanged`。**正确接口是 `org.freedesktop.DBus.Properties`，成员才是 `PropertiesChanged`**。新增 `DoorSensorWorker` 跑在 `QThread("railhmi-door-io")`，持私有 `connectToBus` system bus，订阅直接解包 `ManufacturerData`（`a{qv}` 或已展开 QVariantMap），从 DBus 路径 `dev_XX_...` 推 MAC，无需先经全量轮询；`pushedFrame → QueuedConnection → onPushedFrame` 即刻刷新。GUI 侧零 D-Bus 等待，1s 定时器只重算新鲜度。全量轮询仍严格最多 10s 一次（仅兜底）。
- **物理下限**：真实 BWD1/T1 广播间隔实测 18~22s，软件无法比下一次广播更早知道门状态；本次消除的是额外最多 10s 轮询等待 + GUI 线程最长 3s 阻塞。

## 10:10 追加：门磁延迟结论更正（重要，必须记住）
之前写的「BWD1 广播间隔 18~22s、软件无法更快」是**错的**，已作废并在契约更正。深测（`hmi_verify/ble_latency_probe.sh` / `ble_dedup_probe.sh` / `ble_poll_probe.py` / `ble_gatt_probe.py`）：
- 控制器 `LE Set Scan Enable` 实为 `Filter duplicates: Enabled`；BlueZ `SetDiscoveryFilter(DuplicateData=true)` **只管 BlueZ 内部合并，关不掉控制器/内核去重**。去重开启时 75s 只见 6 个广播，厂商帧计数跳号（6e→70、72→75）= 丢包证据。
- root `hcitool cmd 0x08 0x000c 01 00`（filter_dup=0）后 `Filter duplicates: Disabled`，45s 内 HCI 见 39 个 ADV report ≈ 20 个事件，真实广播间隔 **1~7s（多数 1~5s）**。
- 慢的三重原因：控制器去重丢包 + BlueZ `PropertiesChanged` 节流（关去重后 45s 仍只推 7 次、有 14s 空档）+ 全量轮询 10s。
- 第二层约束：厂商帧内容/计数约 7~10s 才更新（0x95→0x98 用 27s、0xA3→0xA9 用 43s），多数广播是同一帧重发。只把轮询提到 1s 而不关去重，45s 仅 4 次变化。
- GATT 排除：设备 `ADV_IND` 可连接但 Connect 约 10s 才完成，连接后 0 个服务 / 0 个特征，无 notify。
- 5s 可达性取决于设备是否在磁铁动作瞬间生成新帧（PDF 声称会，但 PDF 的 Key 0x08 与「立即上报」已被现场固件证伪，需受控开关门实测）。若会：关去重 + 1~2s 轮询 → 1~2s；若只按 7~10s 周期采样：软件无解，需改设备周期或换有线 GPIO 干簧管。
- 两项实施前置条件（**待用户确认**）：root 发 HCI 命令 / 给 cap_net_admin；把 `poll_interval_ms` 10000→1000 会放宽用户上一轮「最多 10s 读一次」的约束。
