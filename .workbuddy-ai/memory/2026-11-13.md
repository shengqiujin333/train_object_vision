## BLE 门磁：修正「现场没有 T1」的错误判断，接入真实设备

用户质疑「PDF 上写了 T1、我都搜到 T1 了」，实测证明此前判断错误：设备一直在广播，是软件侧两处缺陷导致看不到。

### 现场真实设备（RK3588 / BlueZ 5.64）
- 广播名 `T1`，MAC `C0:6D:9A:AC:C3:87`（Random Static），RSSI 约 -54~-66 dBm，广播间隔约 12~15s。
- btmon 抓到 31B ADV data：`03 08 54 31`（短名 T1）+ `1A FF 07 FF <23B>`。
- 厂商 AD structure：`1A FF | 07 FF | FF FF FF 06 00 63 62 00 ... 00 <计数>`。
  `63 62 00` = 电池 Key 0x63 + 小端 0x0062 = **98%**；末尾字节是每次 +1 的广播计数。
- **关键坑**：PDF 的 `0x07` 帧首被 BlueZ 当作 company id 低位，BlueZ 报告 `company=0xFF07`、value 只有 23B，把 `07 FF` 从 ManufacturerData 值里剥掉了。真实固件在 `<Key,Value>` 报文前还有 `FF FF FF 06 00` 头部，与 PDF「byte5 起即数据报文」不一致。
- 现场广播只带电池 Key 0x63；门磁 Key 0x08 按 PDF 是「状态变化立即上报」，未触发开合时门态保持 Unknown，必须按 unavailable 汇总，不得臆测为已关闭。

### 根因与修复
1. **只调 `StartDiscovery` 时 T1 几乎不进 `GetManagedObjects`**（BlueZ 默认去重 + 临时对象清理）。必须先 `Adapter1.SetDiscoveryFilter({Transport:"le", DuplicateData:true})` 再 `StartDiscovery`，设备对象才稳定可见（`door_sensor_runtime.cpp::startDiscovery`）。
2. **解析器认不出真实帧**：`door_sensor.h` 增加 `DoorFrameFormat::vendor_tolerant`、`kDoorVendorCompany=0xFF07`、`kDoorVendorHeaderSkipLimit=6`；`door_sensor.cpp` 仅在该模式下、尚未解析到任何 Key 时，于有限窗口内跳过固件头部定位第一个合法 Key，超出窗口立即停止。默认严格语义不变。
3. `door_sensor_runtime.cpp::adPayloads` 仅对 `company==0xFF07` 生成「company 小端 + value」拼接候选；`applyPayloads` 对这类候选（前缀 `07 FF`）先试严格布局、失败再试受控宽松布局。其它厂商（Apple/Edifier 等）不生成候选，避免误判。
4. `test_door_sensor.cpp` 新增 `test_parse_real_bwd1_advertisement()`：覆盖真实 25B 帧、带 0x08 的门态帧、越界头部不硬猜、其它厂商不误判。
5. `P6Maintenance.qml` 增加「已收到厂商广播但门态帧未收到」提示行；`rebuildSnapshots()` 增加 `doorUnknown` 汇总字段。
6. `INTERFACE_CONTRACT.md` §9 补入现场实测帧结构与发现过滤要求。

## 门磁「分开磁铁不报警」：真实固件门态 Key 是 0x06，不是 PDF 的 0x08

用户反馈「把门磁分开以后一直没报警，读的是广播数据吧」，实测证明此前对 PDF 的信任有误。

- 磁铁贴合：`ManufacturerData company=0xFF07 value=FF FF FF 06 00 63 62 00 ... <计数>`；
  磁铁分开：`... 06 01 63 62 00 ... <计数>`。**唯一状态位是 `0x06` 后的 1B 布尔值**，0=关闭、1=未关严；
  每次广播都带门态（不是 PDF 说的「状态变化才上报」），`0x63` 后小端 `62 00` = 98% 电量。
- 修复：`door_sensor.h` 加 `kDoorKeyDoorLegacy=0x06`；`door_sensor.cpp` 仅在 `vendor_tolerant` 已确认厂商帧、
  且 Value 必须为 0/1 时才按 `0x06` 判门态，保留 `0x08` 兼容文档。`test_door_sensor.cpp` 改用真实帧建模；
  核心测试 `1495 passed, 0 failed`。`INTERFACE_CONTRACT.md` §9、`P6Maintenance.qml` 提示同步更正。
- 实机闭环（零仿真帧）：分开 → `door=ajar` → `snapshot level=alarm value='1 路未关严'` →
  P1 顶栏/关键状态条/报警栏、P6 卡片、P2 L2 `door_ajar` 事件同步置警；
  贴合 → `door=closed` → `level=ok value='全关'` → 报警栏「当前报警：无」。截图 `hmi_verify/door/OPEN_*`、`CLOSED_*`。
- 读取节奏：HMI 每 `poll_interval_ms=2000ms` 轮询 `GetManagedObjects`，另订阅 `PropertiesChanged`；
  设备广播间隔约 12~15s，`stale_ms=60000ms`；所以开门后约一个广播周期 + 2s 内应报警。
