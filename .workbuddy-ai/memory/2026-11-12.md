## BLE 门磁接入（已完成，板端全链路验证通过）

- 资料：仓库根目录两份扫描版 PDF（USTONE-HA-BSM1-DG / -UM v0.1，型号 BWD1）。本地无 OCR，上传到板端用 `gs -sDEVICE=png16m -r140` 渲染后逐页读图。协议为 **31 字节 legacy 广播**：byte0=0x07、byte1..4=设备ID(小端)、byte5..30 为 `<Key,Value>`；Key `0x08` 门磁 1B（1=感应不到磁铁=未关严）、Key `0x63` 电池 2B 小端百分比（约 5 分钟一次）；广播名 `T1`。**无 GATT/配对流程**，所以不连接、不配对、不写特征值。
- 技术选型：板端**没有 Qt5Bluetooth cmake**，但有 Qt5DBus / BlueZ 5.64。改用 `Qt5::DBus` 直接读 `org.bluez` 的 `ObjectManager.GetManagedObjects` + `Adapter1.StartDiscovery`，订阅 `PropertiesChanged(sa{sv}as)` 刷新新鲜度。`a{oa{sa{sv}}}` 必须**在同一个 `const QDBusArgument` 流上**逐层 begin/endMap；用 `QDBusReply<QVariantMap>` 或先把嵌套值取进 `QVariant` 都会得到签名错误 / `void*` / write-only 报错。`ManufacturerData` 是 `a{qv}`。
- 分层：core 纯 C++17 `door_sensor.{h,cpp}` 负责解析/汇总（稳定 token UNCONFIGURED/NOT_READY/SOURCE_ERROR/UNSUPPORTED/UNVERIFIED/STALE，未核验一律 unavailable）；Qt 层 `door_sensor_runtime.{h,cpp}` 负责 BlueZ → QVariant 快照；`main.cpp` 注入 `railhmiDoorDevices/DoorSummary/DoorAlarmText` 并接 `RailhmiAlarmModel::addLiveEvent` 产生 L2 `door_ajar`。顶栏/关键状态/P1 报警条/P6 维护卡全部接活。配置 `app.door_sensor` 可选，缺省记 `applied_defaults`。
- **重要真值细节**：门磁 Key 只在状态变化时立即上报，电池帧/纯 RSSI 更新不带门磁 Key。用 `Entry::ever_verified` 保证后续无有效载荷的帧只更新新鲜度/电量，**不覆盖已核验的门状态、不打回未核验**；超时后重新收到广播清除 STALE。空 reason 的 UI 文案用「已核验」而不是「正常」，避免被误读成门已关。
